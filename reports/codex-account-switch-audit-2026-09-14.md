## Findings for Cody

This should be a normal ClawDad control that works even when model allowance is exhausted. Application code can handle inspection, login launch, callback tracking, progress, recovery, and verification. You may need to select the correct account/workspace, sign in, consent, or complete MFA/passkeys. An AI agent is unnecessary for the core switch.

Keep the existing Terminal windows and tabs. Wait for affected work and accepted queues to finish, preserve recoverable drafts, and transition only processes that demonstrably need it. A separate recovery journal must protect the operation; manually saved Terminal setups remain unchanged. An exact conversation ID preserves a reference to history, not an in-memory computation or an unreadable draft.

The existing sign-in action is **not a safe account-switch controller**: its success script restarts the shared app server, and its fresh-sign-in option stops that server and logs out before authenticating. It has no complete multi-session preservation transaction. This was source-reviewed and its command strings were confirmed in the installed binary; it was not invoked.

Supported managed browser and device-code login exist in both installed Codex versions. Neither installed protocol exposes an account-list or account-switch method. A retained, securely selectable multi-account credential vault, automatic reload of every running process, and cross-account conversation resume have **not** been demonstrated. The first version should offer deliberate sign-in, not promise a saved-account dropdown that avoids authentication.

Recommend a configurable **2% warning**, with Switch account available at any time, and a deterministic zero-allowance recovery path. The warning is a convenience, not a guaranteed reserve. Keep the existing research-supervisor stopping policy separate.

## 3. What supported authentication provides

OpenAI documents ChatGPT subscription login separately from API-key billing, browser login with a local callback, device-code login, and file/OS credential-store options. Device-code availability can depend on personal or workspace settings. Browser sign-in may require account selection and authentication challenges. The supported browser flow uses Codex's callback/state handling, rather than ClawDad inventing an OAuth exchange. [Authentication documentation](https://learn.chatgpt.com/docs/auth), [CLI login](https://learn.chatgpt.com/docs/developer-commands#codex-login).

The installed 0.153.4 and 0.154.0 schemas both provide managed `account/login/start` types `chatgpt` and `chatgptDeviceCode`, a login ID, completion notification, cancellation, account read, and account update. Neither provides an account catalog/switch endpoint. **Both installed schemas explicitly restrict `chatgptAuthTokens` to internal use**; exclude it from this design even though current [general protocol documentation](https://learn.chatgpt.com/docs/app-server#auth-endpoints) describes an experimental host-managed-token mode. Do not turn this discrepancy into permission to build a refresh-token vault.

Local managed requirements can constrain login method, allowed workspaces, and credential storage. A workspace mismatch must be shown, not bypassed. A destination's remote workspace policy may differ even when no local requirement is configured. [Managed authentication](https://learn.chatgpt.com/docs/enterprise/managed-configuration#manage-authentication-locally).

Account email identifies a sign-in principal for display; the same person may belong to several workspaces. The limits response's backend account ID identifies its entitlement context. `account/read` supplies email/plan but **no workspace name** in the installed schema. Show a verified ID with “workspace name unavailable” until a supported response establishes its name; do not label a local directory or ClawDad pairing workspace as the OpenAI workspace. Missing email is also a supported state. An email-only before/after comparison is insufficient when the same email can select another workspace.

The first version may retain **nonsecret recently used account/workspace metadata** with last-verified timestamps. Selecting an entry means “sign in and verify this identity,” not “this account has valid stored credentials.” Supported login may reuse browser cookies, or may request full sign-in again. CLI `--profile` is configuration selection, not a documented authenticated-account vault. Separate Codex homes isolate more than authentication (history/config/socket/etc.); Keychain namespace isolation and exact-history access must be tested before treating them as independent account profiles. Do not rotate raw `auth.json` files, duplicate refresh tokens, symlink histories across homes, or put secrets in a switch journal.

Prefer the supported OS Keychain credential-store mode for any newly approved switch-managed authentication, with a clear failure if that store is unavailable rather than an unnoticed plaintext fallback. The current file store stays unchanged under this audit. Moving between stores requires its own supported sign-in/migration and verification across every launch path, including the reviewer's ignored-user-config mode. A Keychain entry's existence alone does not prove valid credentials or safe multiple-account isolation.

Do not assume the backend account ID distinguishes every human member of an organizational workspace. The current budget key identifies the reported allowance scope. A future principal/workspace mapping needs supported identity evidence; retain the existing key and ledger while this is unresolved instead of inventing a subject-ID or email-based migration.

**Global credential scope matters:** deferring one session does not isolate it from a shared-store login. Before committing a replacement in a shared store, all consumers of that store must be quiescent/recoverable, or any excluded consumer must be proven credential-isolated. Unknown consumers block that global transition. Changing a global file and leaving “deferred” busy processes running is not a safe v1 design.

Locally retained UUID history makes same-conversation resume technically addressable. It does **not** prove that uploading that history under a different account/workspace is permitted, or that encrypted reasoning, cloud references, images, MCP sessions, organization policy, and model access survive. Cross-workspace history transfer needs explicit user authority and the destination's policy; failed resume must preserve the original history/owner and must never create a replacement conversation.

## 6. Recommended interface and controller sequence

In the existing weekly info popover, add “Codex subscription,” verified email, verified workspace ID/name or an explicit unavailable label, plan, weekly percentage/reset, last refresh, and **Switch account…**. Show short-window or backend exhaustion information separately when relevant. Keep API billing separate and do not add purchase, add-credit email, or reset-credit consumption actions to this flow. The same entry point is available at exhaustion and before it. [Current phone popover](../apps/ios/ClawDadMobile/Sources/ClawDadMobile/WeeklyUsage.swift:120).

The switch panel is a linear preview with per-session rows: current principal/verification source, exact project/thread, state, recoverable draft/queue summary, required transition, and blocker. Controls: Proceed when ready, Cancel before commitment, and Resume recovery. A separately confirmed stop must identify exact active work; it is not implied by Switch. Present mixed/deferred state prominently after partial recovery.

Proposed durable sequence:

1. **Inspect and preview.** Assign one stable operation ID; enumerate credential realms and current owners, account evidence, busy states, accepted queues, drafts, settings and receipts. Reconcile duplicate owners before proceeding. Do not create a snapshot.
2. **Arm an admission hold.** Persist a switch epoch and expected revisions. Hold new main-Assistant turns, project sends, local queue dispatch, workspace launches and research review/continuation admission for the affected credential realm. Already-running work and native queues retain ownership. Preserve typed edits; if manual activity changes the preview, re-inspect. ClawDad cannot prevent commands from an unrelated terminal program; revalidate immediately before commitment and report interference.
3. **Reach a safe boundary.** Allow turns and accepted queues to finish. Any fresh no-ID thread, unreadable draft/image, uncertain receipt, unresolved trust/sign-in prompt, unknown credential consumer, or active subprocess that must survive is a blocker. Display it rather than expiring the wait into a forced stop.
4. **Persist recovery evidence.** Atomic journal plus file/directory synchronization, private permissions and a filesystem controller lease. Capture exact states, content hashes and identity provenance; verify attachment files. Keep optional secret handles separate in OS credential storage; the journal has no tokens/codes/cookies.
5. **Authenticate with the best supported ordering.** Prefer proving destination authentication before stopping an existing process **if an isolated credential staging scope is demonstrated** in the approved experiment. Today there is no established non-committing staging API; managed login may update its credential store as soon as it succeeds. Until isolation is proven, drain and fence the whole shared scope first, keep windows and idle recoverable processes open, then run managed login without a preliminary logout. Do not promise transactional staging/rollback from the current APIs.
6. **Verify destination.** Match the login ID, auth mode, expected email and entitlement/workspace identity, policy, available models, and fresh limits. Wrong identity, incomplete evidence, or API-key mode keeps admission held. An email match alone is not enough. Avoid streamlined auto-selection for switching when it prevents deliberate account choice.
7. **Transition each required runtime.** Use a tested hot-reload path only where positively verified; otherwise cleanly exit only eligible idle Codex owners, leaving their shells/windows/tabs, and resume their exact UUID/cwd/settings through the original native transport. Shared-server restart is gated on all its owned threads; independent background coordinators/reviewers finish first. Include descendant runtimes in ownership reconciliation. No resume into a second transport, task resubmission, or queue replay.
8. **Verify and return control.** Match exact threads and latest persisted histories, uniqueness, settings, drafts, attachments, accepted message IDs, per-runtime destination identity, and quota. Preserve the original account attribution of historical work. Release only the approved holds for verified sessions; queued work whose account authorization changed remains held for explicit continuation. Superseded or uncertain receipts never dispatch again automatically.

The controller should live in a native/service component independent of the managed Codex children. Its deterministic UI, IPC, leases, files and notifications require no model call. If the ClawDad host restarts, it reopens the journal and reconciles; it does not re-run the initiating Assistant message. Existing call/hang-up, speech, microphone and conversation controls remain separate.

## 7. Failure and rollback design

Journal fields: operation/request ID, revision/state, approved source and destination identity metadata, credential-realm reference and epoch, login ID/expiry (no auth URL query/code persisted), controller owner/start time, affected sessions and exact topology, permissions/config provenance, draft/hash/image references, native/app-server queue IDs, accepted-turn boundaries, request fingerprints, per-step before/after/uncertain receipts, and hold/rollback state. Keep a bounded history outside `MainTerminalWorkspace`; do not make named snapshots automatic again.

| Failure | Recovery behavior |
|---|---|
| Duplicate click/request/reconnect | Reuse operation and login IDs while valid; conflict if same ID has different intent. A second controller must acquire the durable lease. |
| Login cancelled/expired/failed before commitment | Cancel the pending login by ID where supported, verify current credential identity, then release only this operation's holds when safe. Keep drafts and manual pauses. Do not assume failure means the credential store remained unchanged. |
| Wrong account or credential store already changed | Stay held and show actual identity. Rollback is a new verified authentication to the source account unless a supported isolated credential slot can safely be reselected. No raw-token file rollback; do not promise silent rollback. |
| Network loss / callback lost | Retain phase and login receipt; reconcile supported account state on reconnect. Do not start another login merely because a completion event was missed. A lost login ID after host failure requires an explicit fresh ceremony and observed-state reconciliation. |
| Unsupported model/effort / workspace policy | Preserve chosen settings and exact history, explain missing access, and ask for a permitted choice. No silent model, workspace or API substitution. |
| Crash/restart after launch dispatch | Reinspect processes, credential epoch, thread locks, latest accepted turns and receipts. Unknown launch outcome blocks another resume. Windows can remain open even when the controller restarts. |
| Partial multi-session recovery | Retain successful bindings. Retry only confirmed missing work. Mark old-account and unverified consumers; never mark the entire switch successful. |
| Exhausted/interrupted turn | Preserve partial result and effect receipts; distinguish unsent text, accepted user turn, native queue and executed tools. User reviews a bounded continuation, not a blind replay. |
| Supervisor or Assistant already stopped | Preserve stop/pause state. An account switch, reset or reconnect is not a start instruction. |

## 8. Usage, thresholds, and autonomy

Installed quota precision is `int32 usedPercent`, not fractional tokens or remaining model calls. The provider's rounding rule is not specified by that schema. ClawDad calculates `100 - usedPercent`; the phone can format decimals but cannot recover precision the provider did not send. A 0% display is not by itself proof that ordinary subscription access is exhausted. Version 0.154.0 adds `ordinaryUsageAllowed`; 0.153.4 lacks it. Preserve unknown rather than infer recovery/exhaustion from percentages or reset times. Current normalization drops that field: this is an identified future UI/controller gap, not a repaired behavior in this audit.

The monitor polls at 120 seconds and permits a cached reading up to ten minutes old; the Mac UI also polls its local endpoint. Consumption can change between reads across many processes or other devices. Short-window throttling, model-specific buckets, weekly limits, workspace spending controls and separately purchased credits can differ. The live response included a credits object; its presence does not establish API billing or authorize using supplemental credits. [Normalization and polling](../lib/codex-weekly-usage.mjs:44).

| Candidate | Benefit | Limit / recommendation |
|---|---|---|
| Warning at 2% | Earlier opportunity to finish work and sign in deliberately. | Recommended initial nonmodal warning, deduplicated per verified account/cycle. No automatic switch or new budget effect. |
| Warning at 1% | Fewer early reminders. | Less time for concurrent work; still cannot guarantee any AI action budget. Offer later as user preference. |
| User-selectable reserve | Can stop new optional work earlier if Cody expressly wants that. | Separate permission/setting; no reserve changed by this audit. Running work may keep consuming. |
| Deterministic path at 0% | Sign-in ceremony, recovery UI and native control need no model generation. | Recommended foundation. Provider availability, authentication challenges, network, and device eligibility still matter. |

There is no defensible conversion from one percentage point to a number of computer-use clicks or minutes. Model choice, context, reasoning, tool interactions and concurrent usage vary; a switch must not depend on spending the final percentage correctly.

Retain the existing account-hashed 20% default, explicit account-wide thresholds, per-supervisor overrides, latches, 5% and 0% alert histories. Existing code rejects account mismatch before review/dispatch and preserves stopped/manual-paused states. [Budget admission](../lib/research-budget.mjs:60), [explicit changes](../lib/research-budget.mjs:132).

Proposed transition policy: source account ledgers/authorizations stay immutable; destination uses its own existing ledger or the normal 20% default. Do not move an exception between accounts or rearm alerts just because of switching. Existing supervisors retain source-account binding and paused/stopped state until Cody explicitly authorizes rebinding to the exact destination, objective and budget. Any such future rebind records both identities and a new authorization revision.
