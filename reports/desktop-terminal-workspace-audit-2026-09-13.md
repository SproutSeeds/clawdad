Three focused interaction gaps should be resolved in the eventual patch, without replacing the engine:

1. **Stale window selection:** desktop grouping takes the last tab as each window’s representative. When representative IDs disappear or change, [render lines 29–35](/Volumes/Code_2TB/code/clawdad/web/main-terminal-workspace.js:29) falls back to the currently selected window. This is a source-confirmed retargeting path, not a reproduced wrong-window Save. Pin the user’s chosen identity, expose staleness and require reselection/verified reconciliation. iPhone uses the first representative and keeps its initial selection; the two clients should receive a common window descriptor rather than derive different representatives.
2. **Reviewed revision versus Restore:** Save/Update validate the library revision. Restore deliberately skips that check and initializes from whichever snapshot revision is current at execution ([433–459](/Volumes/Code_2TB/code/clawdad/native/macos/Sources/ClawDad/MainTerminalWorkspace.swift:433)); both UIs omit an expected snapshot revision. An intervening phone Update can therefore change what a desktop Open will restore. Add a reviewed snapshot-revision guard while keeping accepted-operation retries attached to their original receipt. This is a source-confirmed gap; no race was triggered against real data.
3. **Browsing and pending requests:** opening the current panel enqueues a writing inspect action; desktop pending requests live in origin-scoped `localStorage`, while iPhone uses stable host/account scope. Use read-only library browsing and explicit fresh-window inspection. Audit a changed loopback port/restart with disposable UI state before claiming desktop pending request continuity. Expose durable operation identity on reopening. Scope any storage adjustment to this feature; avoid a new settings architecture.

The Save preflight should bind the reviewed physical window/membership to final capture. Today the save request carries a transient tab ID and library revision, but no reviewed-window fingerprint. Native capture does protect against changing process identity and manual interaction while it scans. A queued request delayed before that scan could still capture a changed lineup. Extend the existing native path narrowly if the current catalog cannot supply a sufficient stable descriptor; never guess identity from a window title.

**Proposed desktop flow.**

Place a compact **Terminal Setups** row immediately above the existing project composer, containing **Save Terminal Setup…** and **Open Saved Setup…**. This is more visible than the existing allowance-style text and avoids hiding a common workflow inside Settings. The tradeoff is one small utility row; keep a native menu shortcut as optional follow-up, not a prerequisite or a second implementation.

Save opens a focused sheet with an exact live-window chooser, snapshot name and ordered tab preview. Show tab name, verified project directory, Codex/shell type and an expandable thread ID; highlight incomplete identity, unrecoverable draft or temporary test-path warnings. If only one window exists, preselect it but still show its count and lineup. Final Save creates a new named setup. Update is an explicit secondary action for a selected saved setup, with a lineup diff and previous-version recovery. Duplicate names should lead to a clear Save-new/Update choice, not an implicit overwrite. Saving never closes anything.

Open presents saved setups with name, capture time, tab count and recoverability summary. Selecting a row only previews it. The primary Open/Restore action restores that exact ID and reviewed revision, shows per-tab progress and uses the existing ownership/reconciliation engine. Where an existing window conflicts, present the supported reuse/separate choices before dispatch. A setup containing already-open exact conversations reuses those owners; it cannot instantiate the same agent again in an independently named window. Keep legacy/recovery records in an expandable group and preserve them all.

Both sheets need Done/Cancel, Escape, restored keyboard focus, clear busy/disabled states, accessible labels, comfortable targets and a scrollable long preview. Leaving a sheet does not cancel an accepted restore. Explanations should say “Reopens the same conversations with their latest saved history. Continue when ready.” Details should explain saved-draft limitations and that stopping a running process loses its in-memory work. Close-window controls remain in their existing separate guarded workflow.
