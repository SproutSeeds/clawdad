# Terminal compatibility, speech recovery and Assistant destinations

Release: Mac **0.7.0 (101)**, signed, notarized, stapled and installed in `/Applications/ClawDad.app`; iPhone **0.7.0 (79)**, VALID and IN_BETA_TESTING in the existing **ClawDad Internal** TestFlight group. Physical iPhone checks below remain open.

## Confirmed causes and behavior

### Terminal control

The installed starting point was Mac 93 and Codex 0.154.0. A blanket `0.153.4` compatibility check rejected otherwise usable composers. There were two additional rendering issues: Codex 0.154.0 draws animated braille sparkles in blank composer cells, including the border above the prompt; and existing accepted queue entries can be clipped to an ellipsis. Those representations prevented exact draft/queue checks.

Compatibility is now evaluated per action from the actual TTY-owning process, mapped executable, process lifetime, exact conversation file, composer and displayed binding. Ordinary shell controls do not depend on a Codex version. Renderer sampling removes a sparkle only after the same cell is observed blank; stable literal braille is preserved. If sampling or identity changes remain ambiguous, input stays protected and the tool explains the missing evidence.

Pasting into an empty recognized composer and native Tab queue verification no longer require an exact version. Destructive nonempty clearing and an unadvertised default Enter shortcut retain a narrow, verified key adapter (0.153.4 and 0.154.0 currently). Future versions can retain other capabilities while an unverified destructive shortcut requires an adapter update or manual action. This deliberately provides partial capabilities instead of disabling all Terminal control.

Previously accepted collapsed queue entries are treated as opaque, unchanged representations. A new queued message still requires complete verification. Queue acceptance is checked after one Tab; an uncertain acknowledgement never causes automatic replay.

Read-only checks through the installed Assistant, repeated on final Mac 101, confirmed the real ClawDad and Erdős sessions are recognized, with their own exact session IDs and executable `/opt/homebrew/Caskroom/codex/0.154.0/bin/codex`. ClawDad exposes busy native queue readiness even with its existing collapsed queued messages. Erdős contains an existing collapsed draft: clear/replace is available with explicit whole-draft authorization; insertion preserves that draft. Neither real project draft nor existing queue was changed.

### Primary speech

The actual selected primary provider is **Doc Reader, Kokoro, local port 8772**. The existing launchd owner is `com.docreader.tts-local`, using the managed local Python environment. Startup logs contain a Kokoro model-cache FileNotFoundError. The cache points to the external Code_2TB drive. The primary service was healthy at inspection; logs lacked enough timestamps to prove that Cody’s specific warning occurred immediately after a reboot. No active fallback was assumed from the warning alone.

ClawDad now checks the selected local engine’s readiness and, when needed, performs one bounded constant-text warm-up whose generated bytes are discarded. Recovery uses backoff, checks the existing installation and launchd owner, and requests startup only through that owner. It waits for unavailable local dependencies rather than creating extra services or initiating model downloads. Periodic checks cover recovery after startup, wake, and service loss. A live service is never repeatedly killed to satisfy readiness.

Synthesis has a deadline that includes the response body and one bounded retry for transient connection/readiness failures. iPhone Assistant playback can use device speech if the primary does not become usable within the initial playback window. Subsequent replies try the selected primary again. Playback tracks completed chunks; recovery speaks only the remaining text. Cancellation and message order are retained, and late primary output cannot play over a reply already assigned to fallback.

Controlled service fixtures ran the actual installed Kokoro/Python service on a separate loopback port: initial readiness **10.686 s**, first synthesis **609 ms**; restart readiness **8.751 s**, first synthesis **466 ms**. Both produced verified 166,844-byte WAVs. This is generated-audio evidence, not audible iPhone playback. The production speech service and Mac were not rebooted for these tests.

### App-server access and ownership

The initial shared server still ran Codex 0.153.4 from a Homebrew `.upgrading` executable path that no longer existed. History reads worked, but creating a thread failed to load configuration. With two read-only checks confirming zero loaded threads, that idle shared service was replaced with the current 0.154.0 executable. No Terminal process was interrupted.

Native startup now uses a stable home working directory. Guarded maintenance detects missing mapped executable/working-directory paths and permits replacement only after repeated empty loaded-thread inventories and exact socket/process ownership checks under the shared startup lock. Loaded threads, including idle ones, retain their owner. Uncertain ownership or a still-stopping process defers recovery.

The Assistant now has supported app-server tools for workspace/thread discovery, inspection, history, creation, archived restoration, resume, local drafts, text/images, native follow-up queuing and receipt reconciliation. New threads use the existing ClawDad approve-mode workspace sandbox; existing threads resume without overriding stored permissions. Permission requests reuse the existing user-decision path. An unmatched or failed approval handler leaves the request unanswered.

A new thread returns its verified ID and registers locally without switching the main app’s selected session. Images are copied into immutable, hash-checked local storage before acceptance; image-only messages are valid. Draft revisions protect saved text and images. Native queue receipts carry stable client message IDs and are correlated with the exact resulting turn and response, including after reconnect/restart. Pending/uncertain receipts are never blindly resent.

## Capability matrix

| Action | Exact Terminal transport | ClawDad shared app server |
|---|---|---|
| Discover and identify | Physical window/tab, TTY, process lifetime, mapped binary, own session | All server pages/sources plus local index; exact UUID and live process owner |
| Read context/history | Current native screen and own transcript | Paginated API; read-only legacy history fallback where available |
| Create | New native tab in the selected physical window; verified new TTY | Explicit new thread in an existing configured workspace; verified UUID; no prompt |
| Restore/resume saved thread | Existing native workflow; never borrow a same-directory session | Explicit restore uses `thread/unarchive` without loading or sending; fresh inspection and separate resume retain native restrictions |
| Insert draft while idle/busy | Empty recognizable composer; no Enter/Tab | Durable Assistant-owned thread draft; independent of running turns |
| Clear/replace | Fresh token + expected representation; supported complete/multiline input; explicit whole-draft authorization for collapsed text | Fresh saved-draft revision and explicit replacement; no submission |
| Shell drafting | Recognized native shell; insert/replace/clear; version-independent | Through the thread’s agent after an authorized task, not a shell composer |
| Explicit keys / special commands | Existing native key/shortcut tools with fresh input identity and intended effect | Agent workflow; no synthetic Terminal keys sent to an app-server thread |
| Enter submission | Separately authorized native action; verified shortcut + receipt | Idle send uses durable native queue acceptance and automatically starts a new turn |
| Native follow-up queue | Busy agent, one observed Tab; supports a new message or existing fully readable draft | `thread/queue/add`; runs after current work, automatically starts when idle |
| Attachments | Existing authorized native image controls; editing preserves attachments | Up to four PNG/JPEG images; retained actual bytes; image-only or text+image |
| Reconnect / duplicate requests | Existing durable receipts and session reconciliation | Durable pre-send receipt + native client message ID, queue/turn reconciliation |
| Control a history owned by the other transport | Keep the existing native owner | Read allowed; resume/send/queue fenced for Terminal/other runtime owners |

Limitations are explicit: unreadable new collapsed queue content, attachment-bearing clear/replace, unresolved prompts, changed identities and unverified destructive key bindings remain protected. Archived entries are discoverable. The real API requires restoration before resumption; `restore_thread` now handles that step explicitly and returns a verified identity without loading or sending. Reading/resuming still requires retained valid history. Missing-source or invalid-lineage histories report recovery guidance without creating a replacement runtime. Native queue semantics were observed on Codex 0.154.0; unsupported future methods report unavailable capabilities rather than substitute steering.

## Inventory and ownership evidence

Before fixture cleanup, the installed tools enumerated **3,452 indexed thread identities across 70 returned pages**, including all server source kinds and the archived index entry. The server listed 216 active histories and zero archived histories; 223 entries had server/local-history evidence, while 3,229 needed further history inspection. Index metadata can outlive history files, so unverified entries remain discoverable and are not presented as proven readable. Two sampled older entries returned “thread not loaded” and “missing source rollout”; seven index-only retained histories were also found, with read-only samples successfully read. Inventory labels are bounded because legacy titles can contain entire very long prompts.

| Surface | Stable identity and owner | Control implication |
|---|---|---|
| Real ClawDad Terminal agent | Own conversation UUID ending `6990fcd8`, foreground TTY `/dev/ttys005` | Native Terminal transport remains authoritative |
| Real Erdős Terminal agent | Separate conversation UUID ending `e8cafa58d`, its own foreground process | Same-directory/title matches never substitute for this identity |
| Shared app server | Private local Unix socket, one verified current-user Codex process | Writes allowed only for this owner or an explicitly resumed unowned saved history |
| Main conversational Assistant | Separate durable conversation, with its own active runtime when responding | Continues coordinating while dispatched app-server/Terminal tasks run |
| Disposable app-server fixture | UUID ending `07813f54`; independent from the Terminal fixture even when directories/history are related | Three ordered turns and a retained image were verified through actual Assistant tools |

Shared history proves identity/history continuity, not shared live control. No verified supported cross-process API was found for injecting a native queue into a Terminal-owned runtime from the shared server. That destination therefore retains its Terminal transport. The shared native API’s queue automatically starts when idle; a busy `send_to_thread` is rejected in favor of explicit `queue_thread`, which does not steer the active task.

## Destination selector

The outlined Terminal/claw button appears in the persistent call-control bar and in text-only chat. It has a 44-point target, selected state, accessible name/value/hint, and Icon glossary explanation. Connection/recovery information remains available above the bar and in the conversation.

The preference belongs to the durable Assistant conversation on the selected Mac. The exact remembered thread/tab is stored separately from the transport. Every user request snapshots its applicable destination; explicit conversational targeting can resolve and update that request’s destination through the Assistant tool. Switching itself creates, moves, submits and replays nothing. Existing tasks, research supervision, native queues and local drafts keep their original owners. Unavailable targets produce an explanation rather than silent rerouting.
