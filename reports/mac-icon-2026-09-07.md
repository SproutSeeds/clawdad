# Mac and iPhone icon consistency — September 7, 2026

Mac build **71** is installed at `/Applications/ClawDad.app`, signed, notarized,
and healthy. It uses the same baby-in-a-claw artwork and burgundy background as
iPhone build **56**. The user confirmed that restarting the iPhone corrected its
stale notification icon, so no additional iPhone build was needed.

## Change

The Mac build still selected `assets/clawdad-claw-hyperreal-icon.png`, a separate
standalone claw image. `native/macos/build-app.sh` now selects the shared
`assets/clawdad-app-icon-1024.png` generated for the iPhone release. All ten Mac
icon renditions are derived from that asset. The native README documents the
shared source and regeneration command so subsequent builds retain it.

The approved artwork and the iPhone assets were preserved. The Mac's embedded
runtime also now contains the current shared app icons.

## Verification

- Native release build, shell syntax check, and all **541 runtime tests** passed.
- The Mac bundle's 1024-pixel icon matches the iPhone's 1024-pixel icon exactly.
  All ten extracted Mac renditions have the same burgundy background, RGB
  `(23, 0, 3)`. The packaged icon was visually reviewed.
- The installed app's registered macOS icon was extracted through `NSWorkspace`
  and visually reviewed. It shows the correct baby, claw, and background with
  macOS's standard rounded frame and lighting. That system rendering is not
  expected to have pixel identity with the unframed source image.
- Apple notarization accepted `a8d5d164-e879-4b58-886c-84bc8f044d0d`; the ticket
  was stapled. Deep signature verification, stapler validation, and Gatekeeper
  assessment passed for the installed app.
- Exactly one installed native app process was running. The active runtime
  matched the installed bundle, including its current shared icon asset.
  `/healthz`, `/v1/native/capabilities`, and `/v1/assistant/state` returned HTTP
  200 with Remote Assist available and the background Assistant online.

The first install verification reached the health endpoint before runtime
activation finished and stopped at the runtime-version equality check. The
app finished activation normally; final verification confirmed matching runtime
markers, current assets, and all health checks. The retained install script now
waits for the activation marker before evaluating service health.

The reported Mac notification itself was not inspected: Computer Use did not
have access to Notification Center. The source audit found no native Mac
notification emitter; the terminal-response pipeline submits metadata to APNs
for the iPhone bundle and supplies no notification icon. Apple documents that
[iPhone notifications mirrored onto Mac carry an iPhone badge](https://support.apple.com/en-us/120684).
The specific Mac alert's origin remains unconfirmed. The iPhone notification
icon was physically confirmed corrected by the user, and the Mac app's separate
branding mismatch is now repaired.
