## Incident reconstruction

### 1. Startup trust: a missing decision workflow after the Enter repair

The originating user request, `99b14dc5-4aec-427c-bdcb-bdfc7bcdd628`, arrived at **22:35:13.649** and asked the Assistant to open the project in Terminal, launch Codex, and send the prepared work. A new shell tab was created, its launch draft was inserted, and a separate shell Enter launched Codex. The trust screen was then observed in tab `9928f258-0ce8-4d37-9ec0-464d60b35a4a`, TTY `/dev/ttys012`, fresh process instance `codex-process-03d46e41808c18991f8f24352f3e559c0c55b2fa0219812050a4991c6f14c941`.

Native inspection `141b5901-80b1-42a5-a805-7bec28784bbb` completed at **22:36:40.294**. The screen asked “Do you trust the contents of this directory?”, with “1. Yes, continue” and “Press enter to continue.” It also explicitly warned that trust allows project-local configuration and prompt-injection risk. This was an agent startup prompt, not a conversation composer. Inspection correctly returned no editable draft.

Enter request **`e544fc4e-5a06-449b-8884-27837c9d0714`** was created **22:36:47.211**, started **22:36:48.259**, and its rejection reached the Assistant by **22:36:48.832**. It used the fresh native token `8234AE02-0711-4676-9E54-BF1F3C3F726D`, `key=enter`, `intent=submit`, and the inspected process/tab. The result explicitly records `keySent:false`, `turnAccepted:false`, `submitted:false`, `verification:enter-not-dispatched`.

**Confirmed cause:** [MacAssistantTerminalInput.swift](../native/macos/Sources/ClawDad/MacAssistantTerminalInput.swift), lines 331–334, requires a supported Codex **composer** for every agent `intent=submit` Enter. A trust menu has no composer, so it is rejected before dispatch. The token was recent and valid enough to reach that guard. This is not a serialization, account, or CLI-version refusal.

There is a historical regression in coverage: build 85's actual Assistant-transport trust fixture accepted a disposable trust prompt with this same explicit key API. Receipt `cf3e8ca6-91f5-4a3f-91f4-ae98a4e163c1`, September 9 at **15:45:15.381**, records `keySent:true` and the resulting empty Codex composer, without a research turn. [trust-fixture-result.json](../native/macos/dist/candidates/assistant-fresh-codex-2026-09-09/trust-fixture-result.json) preserves that evidence. Commit `062cd3f` later introduced the composer-only Enter branch while fixing existing-draft submission. Its safety requirement is appropriate for submitting drafts, but the distinct startup-decision workflow was not retained.

**Classification:** currently unsupported startup choice, caused by a missing/regressed dedicated workflow; misleading generic key guidance. The Assistant chose the previously usable generic Enter tool, but its declared `submit` intent now refers to a conversation submission. The API offers no correctly typed startup-trust decision.

**Authorization and proposed transport:** a trust decision must be bound to the exact live process, directory/worktree, complete recognized trust prompt and selected choice. It should capture Cody's authorization to trust that directory, including loading local configuration/hooks/policies, separately from authorizing the research task. Existing explicit trust authorization can be reused within its scope; “launch Codex” alone should not silently widen trust scope. A dedicated native startup-decision action should dispatch one verified selection and observe the resulting startup/composer state. It should report `trustAccepted` separately from `turnAccepted`. Manual selection on the actual Terminal screen remains the current user-operated route. Generic Computer Use, Control-J, an unscoped Enter, or changing trust configuration behind the prompt are not proposed workarounds. **The real cancer trust prompt was not accepted and its research brief was not submitted in this audit.**

### 2. Initial 2,239-character queue: missing provenance in the insert-and-queue path

Two inspections completed at **22:39:49.503** and **22:40:00.910** with the exact ClawDad session, empty composer, and queue readiness. The user had authorized a follow-up to the working ClawDad agent; the Assistant selected `queue_in_tab` rather than Enter.

Request **`bd4a5243-ed34-48fe-96e5-0b60e7776142`** was created **22:40:31.321**, started **22:40:32.322**, and its failed status was returned by **22:40:50.954**. It requested **2,239 ASCII characters / 2,239 UTF-8 bytes**, SHA-256 `fae8bf03297b4d2b9af7fa67977869010db84f707b3247ac624b9cf204848555`. It stopped with “The draft or Tab queue binding could not be verified. The inserted text remains for inspection; Tab and Enter were not sent.” No durable `preparedAt` exists for this queue request.

Follow-up inspection **`3d631f39-e3b4-4d88-a4f7-f9e48759c7df`** completed **22:45:02.872**, still in worker `02525…` and the same process/session. The screen contained `[Pasted Content 2239 chars]`, a Working header, and literal `tab to queue message`. The draft fields were `textProvenance:opaque`, `queueText:null`, `queueable:false`; capability fields showed no observed Tab binding.

**Confirmed defect:** [MacAssistantBridge.swift](../native/macos/Sources/ClawDad/MacAssistantBridge.swift), lines 590–636, initializes `knownCollapsedDraft` to nil and only supplies it for `useExistingDraft=true`. The new-message path pastes text but never supplies that exact paste to its subsequent queue parser and never records it through `draftProvenance.remember`. [MacAssistantAgentQueue.swift](../native/macos/Sources/ClawDad/MacAssistantAgentQueue.swift), lines 10–12, refuses a collapsed draft without retained text **before it checks the footer**. Thus the exact text is present in the request but unavailable to the safety check intended to verify that paste.

The same missing handoff explains absent provenance on later inspection. It occurred within one worker lifetime, before build 118 was installed and within five minutes of insertion. A restart or natural provenance expiry is unnecessary to explain it. The operation's generic cleanup also invalidates unchanged provenance when no new verified receipt was recorded (bridge lines 158–169).

**Confirmed diagnostic defect:** `tabBindingObserved:false` here does not prove the footer was missing. It was derived from a failed overall queue parse. The literal Tab instruction was visible, while the hidden-text prerequisite failed. These need separate fields and errors.

**Verification:** the audit's isolated production-helper fixture reproduces the exact error with one simulated insertion, zero prepare calls and zero Tab callbacks. The same collapsed frame parses with its exact retained paste supplied. This demonstrates the missing handoff without modifying any product code. It does not propose trusting a character count by itself. The original request stopped before the helper's prepare/Tab stage, and its exact message hash was not found among accepted user messages in the owning rollout.

### 3. Catalog ID rotation: the Mac 117→118 replacement, with Codex preserved

The original ClawDad catalog ID was `49a977ab-0dcc-41b2-81fe-029c159e7835`. Build 118 was installed at **22:46:22.004**, replacing the native app and worker after incident 2. Old-ID inspections started at **22:48:43.673** and **22:48:53.836** and reported unavailable. A refreshed inspection completed **22:49:16.357** for `045a3ed4-55c9-458f-83b7-c8dfaf722fd7`, with the **same** TTY, PID 13634, process instance and conversation.

**Confirmed cause:** [MacTerminalTabs.swift](../native/macos/Sources/ClawDad/MacTerminalTabs.swift), lines 398–407, keeps catalog IDs in memory and assigns a UUID when a native identity is first seen by that catalog. Recreating the app loses this map; it does not imply Terminal created new tabs or Codex created new sessions. A normal refresh preserves IDs while the same native identities remain observed. Losing observations or reconstructing the catalog can also rotate them; the recorded full app replacement is sufficient for this incident.

The source uses Terminal native tab identity where available and TTY/window fallback otherwise. Native tab identity, display/catalog UUID, process instance, persistent Codex conversation, and saved workspace entry are different identifiers. Matching directory names cannot substitute for any of them.

**Current recovery evidence:** installed `observe_tab` successfully rebound the old 118 ID after the later 119 restart using the exact previous TTY + process instance + session, with no selection change. This capability should be central to ordinary Assistant target recovery, not primarily discoverable through research tooling.

**Remaining lifecycle gaps:** inspection tokens and exact hidden-paste provenance are worker-local and correctly become unusable after restart. Old durable request text plus the same collapsed length cannot reauthorize hidden contents. Pending requests must be reconciled with original receipts before any new delivery. The service preserves receipts and stops replaying running work after worker change, but its accepted-queue monitor currently looks up `job.args.tabId` literally; a rotated catalog ID can report a disappeared queue even with its owner still alive ([assistant-runtime.mjs](../lib/assistant-runtime.mjs), lines 285–313). Saved destination references similarly retain their old catalog ID until explicitly resolved. These are confirmed code-level recovery gaps, not proof that an accepted queue disappeared in these incidents.

The release checks preserved the actual Codex processes and saved project roster, but a restart between Assistant actions still broke transient targets and paste provenance. Future install readiness must account for held input transactions and pending receipts, and explain the inevitable reinspection boundary. No worker restart should be scheduled during the eventual reproduction sequence until its explicit restart test phase.

Keep tokens single-use; expose `issuedAt`, `expiresAt`, `workerId` and a specific `inspection_expired` reason instead of indiscriminately extending lifetime or weakening validation.

### 5. Existing 4,508-character draft queue: later validation failure, not the first failure repeated

Inspection **`de2feb86-b5b1-444f-9836-d8cd34286bfb`** started **22:52:51.138** and completed **22:52:55.948** in worker `FEA2…`. It exposed token `975B413F-0415-4F08-B367-03C833D21974`, `textProvenance:unchanged-native-paste`, the **complete exact 4,508-character `queueText`**, and `draft.queueable:true`. `nativeQueue:true`, `tabBindingObserved:true`, and `queue.supported:true` accompanied `queue.ready:false`.

The screen showed a 31m14s Working turn, two background terminals, the collapsed draft and literal `tab to queue message`. Request **`d634f3e0-63da-4903-9dc7-21e8736c9801`** was created **22:53:05.400**, started **22:53:05.626**, and returned the failure by **22:53:12.020**. It used the inspected token, exact tab/session, exact full text, and `useExistingDraft:true`. Start was only **9.678 seconds** after inspection completion. No worker change occurred.

`queue.ready:false` is explainable: the current bridge defines that field as a queue-capable **empty** composer. It describes readiness for inserting a **new** draft, not readiness for queuing an existing one. The Assistant followed the existing-draft tool's documented `draft.queueable` + `draft.queueText` contract. This boolean combination is misleading, but it did not itself reject execution.

The exact error is thrown by the prepare closure at bridge line 636. Therefore the existing-draft token/owner checks and the helper's preceding asynchronous full-draft + queue-area + Tab-footer verification were reached and passed. The subsequent `allowed(text, requireTab:true)` check returned false **before** `/native/prepare` and before Tab dispatch. This failed at a different stage from incident 2.

**Confirmed implementation discrepancy:** asynchronous inspection calls `MacAssistantComposerRendering.read`, which can await multiple stable frames and accumulate observed blank cells. The later guard uses synchronous `normalized` on one new frame. If decoration moves into a blank cell that has not yet been observed blank, the latter preserves the ambiguous character and the queue parser rejects the frame. The synthetic production-helper fixture demonstrates an unchanged 4,508-character draft passing asynchronous inspection while this single-frame check rejects it; observing the new cell blank makes inspection pass again. Literal Braille remains protected. Sources: [MacAssistantComposerRendering.swift](../native/macos/Sources/ClawDad/MacAssistantComposerRendering.swift), lines 53–75; bridge lines 605–636 and 714–722.

**Historical attribution remains unresolved:** the logs lack the individual predicate outcome and dispatch-time frame evidence. The rendering discrepancy is a reproduced possible cause, not a proven historical cause of `d634…`. The smallest additional observation is one structured pre-dispatch diagnostic record identifying the failed predicate, current human-input generation/foreground identity, busy-log read result and turn ID, stable composer hash/provenance generation, and footer/renderer state. A fixture can collect this without logging prompt contents. No further inspection now can recreate that missing 22:53 frame.

The generic action cleanup additionally invalidates the retained paste after a failed queue if no new provenance revision was created. That is a code-level recovery problem: a pre-Tab failure with otherwise unchanged text can turn a later inspection into an opaque paste. It does not justify restoring text from an old receipt blindly; recovery must establish that the original paste and owner remained unchanged.

| Collapsed paste without current provenance | Label is a representation, not full content | Explicit whole-draft clear/replace can be supported; append cannot infer hidden prefix | Separate opaque representation guard and observed accepted-turn verification; no hidden-text inference | Cannot promise exact queued content; inspect/expand through a verified workflow or explicitly replace first |
| Images, clipped input, unresolved menus, persistent ambiguous Braille | Specific supported observations only | Preserve attachments/hidden text; no generic clear workaround | Only separately verified supported input | Unsupported until required evidence is available |
| Owner changed, stale catalog/token, restart, uncertain prior delivery | Read-only exact rebinding and receipt inspection | Reinspect; never reuse old token or infer hidden paste from equal length | Never repeat an uncertain key | Reconcile; never send another Tab under a new ID merely because status is uncertain |

Source limits remain relevant: Terminal plain-text queue/send/insert actions allow at most **16 KiB UTF-8**; native draft inspections live **45 seconds**; paste provenance lives **300 seconds** within its validated worker/context. The broader chat-capacity change does not enlarge Terminal mutation limits. Human input, process changes, history navigation and restart can invalidate earlier observations before their natural expiry.

## Why prior checks passed while this workflow failed

1. **Different queue entry path.** Build 117's strong live evidence used `insert_in_tab` → inspect → `queue_tab_draft` for collapsed content, plus append/edit operations. It did not prove a long `queue_in_tab` request into an empty working composer. The missing provenance branch therefore survived. `live-agent117.mjs` and the archived per-action receipts establish this distinction.
2. **Renderer checks were isolated.** Unit tests exercised known decoration cells, literal Braille, and queue borders. The queue helper tests injected preconstructed snapshots and a successful prepare callback; they did not run the bridge's synchronous guard against a later AX animation frame after asynchronous normalization.
3. **Busy fixtures were quieter.** The earlier live busy fixture ran a controlled sleep before returning. The real ClawDad turn generated substantial ongoing tool output and background-terminal updates. The history confirms activity; that rendering workload increases race opportunities but does not prove the exact failed predicate.
4. **Startup trust regressed in a later feature.** The build 85 trust fixture genuinely passed, then build 112's existing-draft Enter repair narrowed the same key route. The earlier trust fixture was not rerun as a release gate for that change.
5. **Restart checks emphasized durable state and process preservation.** They proved the real agents survived, while catalog tokens/provenance were intentionally ephemeral. Conversation tools continued holding their old transient references. That is a different recovery requirement from preserving the processes or approved Main Workspace roster.
6. **Successful retries did not explain prior failures.** Both the fresh-session and follow-up reports retain earlier input-fence failures. Later independent successful fixtures establish supported cases, not causal diagnosis of every earlier rejection. They should remain explicit unresolved tests, not disappear behind aggregate pass counts.

The prior report's **682 runtime tests** and **268 Mac tests with 10 environment-dependent skips** are historical verification, not new checks run by this audit. This audit ran **eight isolated checks against unchanged production helpers**, including the reproduced new-queue failure and the rendering discrepancy; all eight produced their expected results. [parser-fixture-result.json](../native/macos/dist/candidates/assistant-terminal-control-audit-2026-09-10/parser-fixture-result.json) records zero real key events. These fixtures make no claim that a repair has shipped.

## Prioritized repair proposal — implementation paused

### P0. Make every refusal and partial delivery attributable

Introduce one structured operation receipt and validation result, shared by inspection and dispatch. Persist the operation phase, failed predicate/reason code, timestamp, worker/build/parser/adapter versions, inspection issue/expiry, native/catalog/process/session identities, human-input generation, foreground/lock/AX status, lifecycle read result/turn, draft representation/hash/provenance revision, and observed footer binding. Store hashes/counts and state classifications in diagnostics, not prompt contents or raw private screen text.

Use separate states for `waiting_for_native`, `draft_inserted`, `prepared`, `key_dispatched`, `native_queued`, `working`, `completed`, and `needs_attention`. Every failure must say whether paste, clear, Enter or Tab was attempted and whether the exact result was observed. Persist a settled/failure timestamp. Keep concise user messages such as “The input focus changed; your draft is still there. I haven't pressed Tab.” A missing lifecycle read should say unavailable, not assert the agent finished.

Return action-specific fields: `canQueueNewMessage`, `canQueueExistingDraft`, `tabBindingObserved`, `textKnown`, `blockingReason`, and observed-at times. `queueable` must require nonempty complete authorized text and the binding, not merely a parsed queue-shaped screen. Retain separate busy evidence from renderer capability.

### P0. Repair both queue paths as one guarded transaction

For a new message, verify the empty exact input and original queue, perform one authorized paste, observe its complete or supported collapsed representation, and retain the exact paste evidence through the remaining queue transaction and subsequent inspection. Reuse the verified insertion mechanism rather than deriving trust from label length alone. If paste verification fails, preserve the possible draft, record partial delivery, and do not repeat the paste.

Make final validation use the same stable composer observation as inspection. An unreadable animation frame may wait for bounded read-only stabilization while owner/generation remain unchanged; literal text, private attachments, changed drafts and ambiguous owners remain protected. Never retry input events inside that wait. Recheck the busy lifecycle and live Tab binding before the sole dispatch. If the turn ends, hold the draft and report that queueing is unavailable; ask for an explicit submission decision only when needed.

Retain valid paste provenance after a pre-dispatch failure only when the same input/session/process and human generation are demonstrably unchanged. Prefer bounded per-target provenance over one global receipt; record invalidation reasons. Any restart, uncertain editing, history recall, owner change or unverified focus transition must still remove authority to infer hidden contents. Do not persist hidden-text authority across restart based on an old request hash alone.

### P1. Separate startup decisions from message submission

Add a narrowly scoped native startup decision API with its own inspection/token and explicit choice/authorization fields. Recognize verified trust screens, bind the exact canonical directory and live process, make the trust implications clear, send one intended selection, and observe startup progression without creating a user turn. Keep unknown prompts, sign-in, policy changes and ambiguous choices unavailable unless separately supported. Update the glossary/tool instructions rather than teaching the Assistant to bypass the composer guard.

### P1. Repair catalog, destination and receipt reconciliation across worker lifetimes

Make the display catalog ID explicitly transient and retain a stable target descriptor: Terminal native identity/TTY, process start instance, conversation ID when present, and worker/catalog generation. Apply the existing exact `observe_tab` rebind logic to destination references and pending/accepted receipt monitoring. Preserve original request fingerprints and owner fields; record aliases/rebinding rather than changing the meaning of an accepted request.

A queued operation whose target changed before dispatch requires fresh evidence. An operation that may have dispatched must reconcile against its original owning transcript and queue; it must never be automatically re-created for a newly assigned catalog ID. An old conversation ID with a different live process is not continuity. Record the full owner in queue preparation as well as the persistent conversation and prior turn.

On update, let an active native transaction settle or mark uncertainty explicitly. Avoid installing between an inspected held draft and its requested follow-up without accounting for the loss of transient proof. After reconnection, automatically refresh/rebind safe references, invalidate short-lived capabilities explicitly, preserve actual drafts, and explain the required fresh inspection. Test delayed native-result receipts from the old worker against the new worker generation.

### P1. Tighten acceptance evidence and Assistant usage

Keep request IDs stable from first intent through status polling. Same-ID/different-text requests must reject; same-ID repeats return the same receipt. Two separately authorized identical messages need separate ordered acceptance evidence, not accidental matching to one turn. Require original process/session ownership, prior-turn boundary, observed queue order and exact authorized content before declaring the follow-up working. Save raw text hashes plus any explicitly allowed CRLF/edge normalization; never use UI wrap normalization as proof that source content is identical.

Preserve earlier native queue items as opaque, ordered entries if clipped. If a newly queued item is unreadable, record one Tab and wait for its matching accepted turn; never repeat it. Reconciliation after restart must scan from durable offsets/boundaries rather than relying only on a fresh eight-MiB runtime tail when substantial output may have intervened.

Assistant instructions should require: compose the outgoing text before obtaining a short-lived token; inspect the exact intended input immediately before edits/queueing; use `queue_in_tab` only for empty working input and `queue_tab_draft` only for complete observed/retained existing text; use clear/replace/append only for the explicitly authorized edit; read the original receipt after partial failure; rebind by exact owner instead of searching by directory; and never turn a user-authorized Tab request into Enter. A past failure followed by an independent success remains part of the diagnostics and test plan.
